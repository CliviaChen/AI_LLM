# 用户故事 · 控制室 v1

> 配套 `docs/PRD-control-room.md`。采用 3 C's（Card / Conversation / Confirmation）与 INVEST。
> Design：无 Figma。视觉规范以 `control-room/client.js` 的孟菲斯硬边体系与 `control-room/docs/DETAIL.md` 为准。

## Job stories

1. **当我两节课之间只有 40 分钟**，我想直接看到"现在动哪张卡最划算"，这样我不用先花十分钟回忆进度。
2. **当我想知道这个项目到底推进到哪**，我想点开就看到进度、任务和最近几次会话，而不是只能进对话从聊天记录里翻。
3. **当我的数据脚本在跑**，我想知道它是还在跑、还是卡在等我确认，这样我敢切去处理另一个项目。

## Epic A · 状态

### S1 看到三种状态

**Description**：作为学生，我想在卡片上区分「空闲 / 运行中 / 等你确认」，这样我能一眼知道哪些项目需要我。

**Acceptance Criteria**
1. 状态只可能是 `idle`、`running`、`waiting`。
2. `waiting` 显示具体原因：待审批 / 计划待审 / 待回答。
3. 同一项目多会话时，优先级 `waiting` > `running` > `idle`。
4. 运行与等待都用荧光绿脉冲，但等待用方形点 + 绿描边，运行用圆点 —— 不只靠颜色。
5. 宿主没提供状态 hook 时全部降级为 `idle`，不报错。

## Epic B · 焦点

### S2 焦点条

**Description**：作为学生，我想看到最多三张"现在该做"的卡。

**Acceptance Criteria**
1. 最多 3 项；候选为 0 时不渲染。
2. 排序：等待 → 今天/明天截止 → 7 天内截止 → 运行中 → 7 天内动过。
3. 点击焦点项进入该项目的详情（与点卡片一致）。
4. 同一输入多次渲染顺序稳定。

### S3 焦点解释原因

**Acceptance Criteria**
1. 每项带原因：`待审批` / `明天截止` / `3 天前动过`。
2. 原因与排序依据一致，不矛盾。
3. 原因文本可被读屏朗读。

## Epic C · 项目详情

### S4 进入详情

**Description**：作为学生，我想点卡片进入项目详情，而不是直接被扔进对话。

**Acceptance Criteria**
1. 点击卡片后显示详情，卡片墙被替换，**不触发**任何会话打开。
2. 详情显示项目名、阶段、截止、当前状态。
3. 详情有四个视图标签：概览 / 看板 / 任务 / 会话，默认概览。
4. 详情可键盘操作，标签可聚焦并切换。

### S5 返回

**Acceptance Criteria**
1. 详情有「← 返回」，点击回到卡片墙。
2. 返回后卡片墙的排序、状态、元数据与进入前一致。
3. 返回不丢失已保存的任务与元数据。

### S6 进入对话

**Acceptance Criteria**
1. 详情头部有主按钮「进入对话」，点击打开该项目的对话。
2. 打开对话前不丢失详情里的未保存输入（或明确提示为即时保存）。
3. 按钮可键盘激活。

## Epic D · 看板

### S7 看板

**Description**：作为学生，我想在一个视图里看到这个项目的活动与进度。

**Acceptance Criteria**
1. 显示四项指标：会话数、任务完成 n/m、距截止天数、最近活动时间。
2. 显示最近 14 天每天的活动柱（按会话更新时间计数），零值有可见占位。
3. 任务进度条与任务数一致；没有任务时进度为 0。
4. 数据全部来自宿主会话与本地任务，不虚构指标。

## Epic E · 任务

### S8 新增任务

**Acceptance Criteria**
1. 输入框 + 「添加」按钮；空输入不添加。
2. 回车也能添加。
3. 新任务追加到列表末尾并立即出现。
4. 任务与当前项目绑定，不影响其他项目。

### S9 完成与删除

**Acceptance Criteria**
1. 勾选可切换完成状态，完成项有删除线与降低透明度。
2. 删除可移除任务，不影响其他任务。
3. 两个操作都有可访问名称，可键盘完成。

### S10 刷新后仍在

**Acceptance Criteria**
1. 任务存入 `localStorage`（键 `control-room:meta`）。
2. 刷新后任务、完成状态、顺序不变。
3. `localStorage` 不可用时当次会话内仍可用，不报错。

## Epic F · 会话

### S11 会话列表

**Description**：作为学生，我想在项目里看到历史会话并直接打开某一次。

**Acceptance Criteria**
1. 列出该项目的全部会话，按更新时间倒序。
2. 每条显示标题（无名时显示"未命名会话"）与相对时间。
3. 点击打开**该条**会话；宿主不支持时回退为打开项目。
4. 没有会话时显示引导文案。

## Epic G · 元数据

### S12 阶段、截止与下一步

**Acceptance Criteria**
1. 阶段四选一（起步/进行/待复核/已交付），再次点击可取消。
2. 截止使用原生日期输入，可清空。
3. 「下一步」为单行文本，可留空。
4. 卡片上回显阶段与截止；未设置时不显示占位。

## Epic H · 首次使用

### S13 首次引导

**Acceptance Criteria**
1. 首次进入显示一行说明（点卡片进详情，四个视图）。
2. 点「知道了」后不再自动出现（本地标记）。
3. 没有项目时显示空状态引导。

## Epic I · 无障碍

### S14 键盘与读屏

**Acceptance Criteria**
1. 卡片、焦点项、标签、返回、任务操作均可 Tab 到达并激活。
2. 焦点环对比度 ≥ 3:1（深浅主题各自验证）。
3. 状态不只靠颜色：同时有文字标签。

### S15 减少动效

**Acceptance Criteria**
1. `prefers-reduced-motion: reduce` 关闭脉冲与悬停位移。
2. 关闭动效后状态仍可通过文字与静态描边区分。

## Epic J · 整理与记录（v1.1）

### S16 右键菜单

**Description**：作为学生，我想右键卡片就能归档或隐藏项目，这样墙上只留正在推进的。

**Acceptance Criteria**
1. 右键卡片弹出菜单，含「归档项目」「隐藏项目」「会话收藏与备注…」。
2. 归档/隐藏后卡片从网格与焦点条消失，网格下方出现「显示已归档 / 隐藏（n）」。
3. 恢复后卡片带"已归档/已隐藏"标记，且可再次通过菜单取消。
4. Esc 或点击空白处关闭菜单。

### S17 会话收藏与备注

**Acceptance Criteria**
1. 会话行左侧星标可切换收藏状态，右侧「备注」展开输入框。
2. 二者与项目元数据同样存在 `localStorage`，刷新后保留。
3. 星标与备注都有可访问名称。

### S18 时钟

**Acceptance Criteria**
1. 右上角显示 `HH:MM`（最大字号）、`YYYY.MM.DD` 与系统星期。
2. 分钟随时间自动更新。
3. 日期与星期为小号大写字母间距排版，符合孟菲斯字体语言。

### S19 记录

**Acceptance Criteria**
1. 左下角按钮打开记录抽屉，可切换日 / 周 / 月。
2. 显示：窗口内已完成项目数、会话数、最活跃时段、Token。
3. 已完成数依据「标记为已交付」的日期；无日期的旧项目不计入。
4. Token 取不到时显示 `—` 与「宿主未提供」，不估算。

### S20 报告导出

**Acceptance Criteria**
1. 记录面板右上角提供「复制」与「下载 .md」。
2. 导出内容包含区间、四项指标与已完成项目列表。
3. 文件名含尺度与日期；失败时不抛出未捕获错误。

### S23 最活跃时段按 token 计算

**Description**：作为学生，我想知道我把 token 花在了什么时候。

**Acceptance Criteria**
1. 日尺度显示一天内 token 最多的**连续 3 小时**，形如 `13:00—16:00`。
2. 周尺度显示一周内 token 最多的**一天**。
3. 月尺度显示 token 最多的**一周**（周一起算，形如 `11-23—11-29`）。
4. 排名用净消耗（input+output），不用含缓存的总消耗。
5. 读不到对应小时/天/周的 token 数据时，整个「最活跃时段」面板移除，不显示 `—`。

### S24 右键重命名工作区

**Description**：作为学生，我想在控制室里直接改工作区名字，而不用切到侧边栏。

**Acceptance Criteria**
1. 卡片右键菜单第一项是「重命名工作区…」，有分隔线与归档区分。
2. 点击后弹出独立模态，输入框预填当前名称。
3. 「确定」调用 `POST /api/control-room-rename` → 宿主 `workspaceController.rename({ workspaceId, title })`。
4. 成功后侧边栏里的工作区名称同步更新；卡片立即显示新名字。
5. 空名称在发起请求前就被拒绝；重名等宿主错误显示在弹窗里，弹窗不关闭。
6. Esc、点击遮罩、「取消」均可关闭，关闭不发请求。

## Epic K · 阶段与账号（v1.2）

### S21 阶段配色

**Description**：作为学生，我想一眼从卡片颜色看出项目阶段，而不用读文字。

**Acceptance Criteria**
1. 五个阶段各有独立色块：未选择（虚线中性）、起步（青）、进行（琥珀）、待复核（洋红）、已交付（墨黑）。
2. 阶段同时改变卡片底色（13% 着色）与色块文字加粗。
3. **荧光绿只用于运行/等待脉冲**，任何阶段都不使用荧光绿。
4. 未选择阶段的卡片保持中性，不显示占位色块。

### S22 Token 用量

**Description**：作为学生，我想在记录里看到真实的 token 用量，而不是一个 `—`。

**Acceptance Criteria**
1. Host 半边读取本机会话日志（`session.v4.jsonl.zstd`，多帧 zstd），按时间窗口汇总。
2. 同时提供两种口径：净消耗（input+output）与总消耗（totalTokens，含缓存）。
3. 数据经 `GET /api/control-room-usage?scale=day|week|month` 返回；仅 owner Peer 可调用，其他返回 403。
4. 同一路由顺带返回账号余额（`deepseekAccount.getBalance`）。
5. 读取失败时显示"需要重启 DSH"或具体错误，不显示编造数字。
6. Host 改动需重启后生效；客户端在路由缺失时回退为 `—`。

## Definition of Done

- `node scripts/verify.mjs` 全部通过（含行为断言：点卡片进详情、加任务、开会话、返回）。
- `node --check control-room/client.js` 通过。
- 深浅两套主题下文案与对比度自查。
- 不新增第三方依赖。
- README / DETAIL 与实现一致。
