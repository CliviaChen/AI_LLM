# 控制室 · 产品设计方案

> 面向：在校大学生（首版聚焦金融相关专业） · 核心命题：**用工作台提升"项目推进效率"**
>
> 方法：PM Skills（`create-prd`、`opportunity-solution-tree`、`value-proposition`、`prioritization-frameworks`、`north-star-metric`、`user-personas`）
>
> 状态：v0.1 草案。文中所有分值与百分比都是**待验证的假设**，已逐处标注；没有引用任何本机数据。

---

## 0. 一页纸

| 项 | 内容 |
|---|---|
| 一句话定位 | 控制室是金融学生的**项目驾驶舱**：把散在文件夹、聊天窗口和待办里的学习项目，收拢成一屏可控的卡片，并永远告诉你"下一步做什么"。 |
| 目标用户 | 需要按周交付成果的本科生：课程报告、案例作业、竞赛论文、科研打杂 |
| 核心痛点 | 不是"事情太多"，而是**每次开工都要重新找回上下文**：翻文件、想进度、决定先做哪个，20 分钟就没了 |
| 解法 | 卡片即项目（状态/截止/下一步） + 今日焦点 + 金融任务模板 + 等待可⻅ |
| 北极星指标 | 每周有效推进的项目数（WPA） |
| 首版不做 | 记账理财、课程表、社交、替代 Excel/IDE |

## 1. 背景与"为什么是现在"

**现状**：控制室已经能用三列卡片列出全部本地工作区，运行中的项目会以荧光绿硬投影脉冲提示。它解决的是"看得见"，但还没解决"推得动"。

**问题依据**（外部，仅作方向参考，不是本机数据）：

- 学习过程中的应用切换有实测成本：一项针对数字学习会话的研究测得每次会话约 **14 分钟**的切换损失，并指出任务切换后效率下降 10–20%（[From Bits to Breaks, AIJR 2025](https://proceedings.aijr.org/index.php/ap/article/view/92)）。
- 一项 56 人（15–20 岁）的问卷中，**78%** 的学生表示难以管理学术截止日期（[SBC ERIMT](https://sol.sbc.org.br/index.php/eri-mt/article/download/39587/39359/)）。样本小，只作方向。

**为什么是现在**：AI 已经能完成"读长文档、跑数据、写初稿"这类重活，学生的工作从"长时间打字"变成"**多段长任务 + 频繁等待**"。等待期间没有状态提示，人就会去刷手机——工作台正好卡在这个缝里。

**为什么先做金融方向**（回答"着重金融"）：

1. **任务形态最匹配**：金融作业天然是"取数 → 清洗 → 建模 → 出结论 → 写报告"的多步骤长链路，单次动辄十几分钟，最需要"状态可见 + 断点可续"。
2. **模板收益最高**：财报三表、DCF、回测的骨架高度标准化，一次封装可以反复复用。
3. **交付物明确**：报告、模型、图表——便于做"成果归档"和"周报"，也就是可度量的效率。
4. **人群密度高**：经管类学生数量大，且普遍有 Python/Excel 基础，上手成本低。

> 注意：这里的"金融"指**金融专业的学习与项目工作流**，不是个人记账/理财。后者与"提高工作效率"无直接关系，已列入不做清单。

## 2. 目标与关键结果

**Objective**：让金融专业学生在**同样的周投入时间**下，推进更多项目、更少空转。

| KR（SMART，均为 2 周 beta 内的目标假设） | 现状 | 目标 |
|---|---|---|
| KR1 每周有效推进的项目数（WPA，见 §8） | 基线待测 | 从基线提升 ≥30% |
| KR2 "打开控制室 → 点进项目"的决定时间 | 待测 | 中位数 ≤ 10 秒 |
| KR3 使用过至少 1 个金融模板的活跃用户占比 | 0 | ≥ 50% |

## 3. 市场细分（按"任务"分，不按人口属性分）

| 细分 | 他们要完成的活 | 典型约束 | 首版是否服务 |
|---|---|---|---|
| **S1 课程交付型** | 每周/每两周交一份报告或作业：读材料、跑数据、写结论 | 时间被课表切碎，单块可用时间 30–90 分钟 | ✅ 主战场 |
| **S2 竞赛/科研型** | 数学建模、金融挑战赛、大创：周期 1–3 个月，需复现与协作 | 长任务多、版本多、要交论文/答辩 | ✅ 次战场（只做单人版） |
| S3 求职实习型 | 作品集、简历项目、面试准备 | 阶段性、非每周 | ❌ v2 再做 |

**约束**（三类共有）：不会为工具付费；设备多为 Windows 笔记本；数据敏感（未发表的作业/竞赛数据）；容忍度低——工具如果第一周没省时间就会被弃用。

## 4. 价值主张（6 段 JTBD）

### S1 课程交付型

- **Who**：金融/经济专业本科生，每周有 1–2 个必须交付的作业或案例报告。
- **Why**：他们的活是"把一堆数据和材料变成一份有结论的报告"。卡点不在写，而在**开工**：打开电脑后要花十几分钟想"上次做到哪、先做哪个"。
- **What before**：文件管理器 + 微信/QQ 传的材料 + 浏览器标签页 + 手写待办。结果：同一份数据存三个版本；打开 5 个窗口才想起昨天卡在哪个表；长任务跑着跑着开始刷手机。
- **How**：控制室把每个项目变成一张卡（阶段 / 截止 / 下一步），一屏看全；点进去就是上次的会话，不用找；金融模板一键铺好目录与起手提示；任务在跑或等你确认时，卡片直接变状态。
- **What after**：从"打开电脑"到"开始产出"从十几分钟压到 1 分钟内；等待时间被转成"处理另一张卡"；期末回看时，每个项目的产出都在原位。
- **Alternatives**：Notion/飞书（要手工维护，记录和工作现场分离）、番茄钟（只管时间不管项目）、文件夹+Excel（零成本但零结构）、DSH 原生侧边栏（能列会话，但不表达"项目阶段与下一步"）。**我们赢在"工作现场同屏"**——卡片背后就是真实运行的会话和文件，不是另一个待办清单。

**价值主张陈述**：给每周都要交作业的金融学生，控制室把"重新找回上下文"的成本降到一次点击，让等待中的长任务变成可见、可切换的状态。

### S2 竞赛/科研型（精简）

- **Who**：参加建模/金融竞赛或跟导师做课题的学生。
- **Why**：长周期、多次迭代，最怕"跑完发现参数错了"和"复现不出来"。
- **What before**：脚本散落、结果图命名混乱、版本靠复制文件夹。
- **How**：项目卡记录阶段与里程碑；模板内置"复核清单"与"结果命名规范"；长任务状态可见。
- **What after**：随时能回答"这个项目现在到哪一步、下一步是谁的活"。
- **Alternatives**：Git（学生普遍不用）、实验记录本（不连现场）。

## 5. 机会与方案（Opportunity Solution Tree）

**期望结果（单一）**：提高 WPA —— 每周有效推进的项目数。

**机会分**：`Opportunity Score = Importance × (1 − Satisfaction)`。下列分值**全部是假设**，需 5–8 场访谈校准（1–5 分制后归一化）。

| # | 机会（用户视角） | 重要度* | 满意度* | 机会分* |
|---|---|---|---|---|
| O1 | "我不知道上次做到哪，得先翻半天文件" | 0.9 | 0.3 | **0.63** |
| O2 | "几个项目同时压着，不知道先做哪个" | 0.85 | 0.35 | **0.55** |
| O3 | "跑数据要等，等的时候我就去刷手机了" | 0.8 | 0.3 | **0.56** |
| O4 | "每次都重新搭环境和模板，重复劳动" | 0.75 | 0.3 | **0.53** |
| O5 | "期末/求职时找不到当时的产出" | 0.6 | 0.4 | 0.36 |

> *假设值，非调查结果。

### 每个机会至少 3 个方案

| 机会 | 方案 A | 方案 B | 方案 C | 选择 |
|---|---|---|---|---|
| O1 上下文丢失 | 卡片显示"上次会话 + 最后改动" | 自动生成"上次做到哪"摘要 | 手动写进度备注 | **A**（零维护，信息已在宿主）；B 作为 v2 |
| O2 不知先做哪个 | 今日焦点：按截止 + 等待状态排序 | 手动排优先级 | 日历视图 | **A**（不做排序心智负担） |
| O3 等待空转 | 卡片显示"运行中 / 等你确认"，并在完成时高亮 | 桌面通知 | 强制番茄钟 | **A**（用宿主已有的 pendingInteraction 信号） |
| O4 重复搭建 | 金融任务模板（目录 + 起手提示 + 交付清单） | 复用上次会话 | 代码片段库 | **A** + B 轻量复用 |
| O5 成果难找 | 项目卡聚合产出清单 | 云同步 | 手动导出 | v2（首版只做本地聚合） |

## 6. 方案设计

### 6.1 信息架构与核心流程

```
控制室（一屏）
├── 今日焦点条：最多 3 张"现在该动"的卡（等待你 > 今日截止 > 最近活跃）
├── 卡片网格：三列，按需换行（已实现，无倾斜，硬投影）
│   └── 卡片 = 项目：名称 · 阶段 · 截止 · 状态 · 下一步
└── 卡片展开（同屏侧栏或二级视图）
    ├── 最近产出（会话/文件/图）
    ├── 模板入口
    └── 复核清单
```

**核心流程（S1，目标 < 60 秒）**
打开控制室 → 看到焦点条第一张（"等你确认"或"明天截止"）→ 点击 → 恢复到该项目的会话与文件 → 按模板继续 → 完成后卡片回到"空闲"。

### 6.2 卡片语义（v1）

| 元素 | 取值 | 来源 |
|---|---|---|
| 阶段 | 起步 / 进行 / 待复核 / 已交付 | 用户一次性设置，可由模板默认值带出 |
| 截止 | DDL 或"无" | 用户填写（唯一必填的元数据） |
| 状态 | 空闲 / 运行中 / **等你确认** | 运行中已接入（现有卡片在用）；等你确认来自宿主的 `pendingInteraction`，首版需接线 |
| 下一步 | 一句话（默认取模板的下一检查项） | 模板 + 用户可改 |

**设计原则**：一屏一决策；状态即行动（卡片上的状态必须对应一个可点的动作）；元数据最多填两项，其余自动推断。

### 6.3 金融任务模板（三个，够用即可）

| 模板 | 输入 | 工作台自动做的事 | 交付物 |
|---|---|---|---|
| **财报三表速读** | 年报 PDF / 链接 | 建目录、生成提取脚本骨架、给三表 + 关键比率清单、要求标注页码出处 | 一页摘要 + 比率表 |
| **DCF 估值骨架** | 假设表（增长/折现/永续） | 建模型文件、敏感性分析模板、检查清单（单位、口径、终值占比） | 估值表 + 敏感性图 |
| **数据清洗与回测** | 行情/财务 CSV | 建清洗脚本、缺失值报告、回测框架与结果命名规范 | 清洗后数据 + 图 + 结论 |

每个模板都带**复核清单**（unit test 式的自检项），直击"AI 产出不可信"的问题。

### 6.4 等待可见（本方案的技术支点）

DSH 会话本身已有"等待用户确认 / 计划待审 / 等待回答"的状态。控制室把它提升为**一等视觉状态**：这类卡片用荧光绿脉冲（已实现），并置顶到焦点条。这是把"等待"从焦虑源变成可调度的时间片。

### 6.5 视觉

沿用已落地的孟菲斯风格：硬边 2px 描边、9px 零模糊硬投影、方形卡片、荧光绿作为唯一"需要你"的信号色。**状态用形状和位置区分，不只靠颜色**（无障碍要求）。

`Score = (Reach × Impact × Confidence) / Effort`，Reach = 首版 beta 20 人中会用到的人次/周。

|---|---|---|---|---|---|---|
| 卡片状态三分 + 等你确认置顶 | 20 | 3 | 0.9 | 2 | **27.0** | v1 |

## 8. 指标

**北极星**：**WPA（Weekly Projects Advanced）** = 一周内"有效推进"的项目数。
有效推进 = 该项目在本周满足任一条：① 完成一次产出型会话；② 在 DDL 前跨过一个模板里程碑；③ 处理掉一次"等你确认"。

| 层级 | 指标 | 目标（beta 4 周） |
|---|---|---|
| 北极星 | WPA / 人 | +30% vs 基线 |
| 输入 | 卡片点击率（会话启动/卡片打开） | ≥ 60% |
| 输入 | 模板使用率（用模板启动的项目占比） | ≥ 50% |
| 输入 | 等待响应时长（等你确认 → 处理） | 中位数 ≤ 10 分钟 |
| 护栏 | 决定时间（打开 → 点击） | ≤ 10 秒 |
| 护栏 | 卡片陈旧率（14 天未动的卡占比） | ≤ 30%，超了说明卡片在堆积 |
| 护栏 | 元数据完整率（填了 DDL 的项目） | ≥ 70%，低于则自动推断 |

**埋点**：`workbench_open`、`card_open`、`template_start`、`pending_shown`、`pending_resolved`、`focus_click`、`weekly_report_view`。**本地计数 + 用户可见**，不上传；beta 阶段用 2 周日志访谈替代服务端埋点。

## 9. 首版范围与不做的事

**v1 必做**：卡片状态三分（含"等你确认"）+ 今日焦点 + 项目元数据（阶段、DDL）+ 财报三表模板 + 空状态与首次引导。

**v1.1**：DCF、回测模板、周报。

**明确不做**：

- 记账/预算/理财（与效率命题无关）
- 课程表、成绩管理（另一个产品）
- 团队协作与评论（先解决单人闭环）
- 云同步与账号体系（本地优先，隐私即卖点）
- 替学生写作业（模板给骨架，不给答案）

## 10. 风险与假设（Pre-mortem）

| 假设 | 重要性 | 不确定性 | 验证方式 |
|---|---|---|---|
| A1 学生愿意为每个项目填一个 DDL | 高 | 中 | 访谈 + 首周完成率 |
| A2 "等你确认"的状态真能减少空转 | 高 | 中 | 对比 beta 前后等待时长 |
| A3 金融模板能显著减少搭建时间 | 高 | 低 | 计时测：有/无模板各做一次 |
| A4 卡片墙比列表更利于决策 | 中 | 高 | A/B：列表 vs 卡片，测决定时间 |

**失败预演（半年后失败，最可能的原因）**：

1. **变成又一个待办清单**——元数据要手工维护，两周后没人更新。→ 对策：只强制 DDL 一项，其余自动推断；卡片陈旧率做护栏。
2. **模板被当成"作业代写"**——产出质量不可信，学生不再用。→ 对策：模板只给结构与清单，要求标注出处。
3. **"今日焦点"排错**——推错任务，用户失去信任。→ 对策：可一键"今天不做"，并记录原因。
4. **性能/兼容**——长会话多时卡片卡顿。→ 对策：只订阅必要状态，限制卡片数量与动画。

## 11. 验证计划（两周）

1. **5–8 场访谈**（金融专业，每场 30 分钟）：只问过去行为，不问意见——"上一次交作业前 30 分钟你做了什么？"
2. **日记研究**：7 名学生，每天记录"开工前的空转时长"和"等待时长"。
3. **两个快速实验**：
   - 模板实验：同一份财报作业，有模板 vs 无模板，计时对比。
   - 焦点实验：焦点条 vs 无焦点条，测决定时间与点击率。
4. **判定门槛**：若 A1（DDL 填写率）< 50%，则改为自动推断截止（从课程/文件名），不推 v1 的手填方案。

## 12. 路线图（按结果，不按功能）

| 阶段 | 交付 | 对应的结果 |
|---|---|---|
| **Now**（已实现） | 三列卡片、运行中脉冲、硬边视觉 | "看得见" |
| **Next**（4 周） | 状态三分 + 焦点条 + 元数据 + 财报模板 | WPA +30%、决定时间 ≤10 秒 |
